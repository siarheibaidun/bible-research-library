# Unified Bible index

The unified SQLite file contains the project's Russian Synodal, KJV, Dutch De Heilige Schrift 1917, Hebrew/Aramaic WLC and Greek UGNT text, their existing verse mapping evidence and raw source word annotations. It also embeds the existing Russian passage search and new Russian, English and Dutch passage indexes. English and Dutch thematic retrieval uses the historical KJV and 1917 Dutch texts, not modern NKJV, HSV or NBV21. Matthew Henry commentary remains a separate dataset.

## Build

Starting with the three existing snapshots generated by the previous project workflows:

```sh
python3 scripts/build_unified_bible.py \
 --bible /path/to/bible-research-search.sqlite3 \
 --originals /path/to/originals_dutch.sqlite3 \
 --passages /path/to/russian_bible_passages.sqlite3 \
 --output /path/to/bible-research-unified.sqlite3
```

The builder verifies source hashes, source integrity, and compatible KJV and Russian editions; it will not overwrite an existing output. The output preserves legacy tables and metadata, all original-language USFM and morphology, source and mapping license notices, and records the input snapshot hashes. It updates four UGNT/KJV split-verse mappings using a comparison of these editions: 3 John 1:14–15 ↔ portions of KJV 1:14; UGNT Revelation 12:18 and 13:1 ↔ portions of KJV Revelation 13:1. Revelation 12:18 has an additional textual variant: the Greek says “he stood” where KJV says “I stood”.

The original `search.py`, `question_search.py`, and `original_search.py` can read the unified database. For `original_search.py cross`, pass the same unified database as `--database` and `--bible-database`. The historical RU/KJV `search.py --translation both` retains its previous meaning.

## Bidirectional comparison

```sh
python3 scripts/unified_search.py --database /path/to/bible-research-unified.sqlite3 compare --from russyn --book Псалом --chapter 22 --verse 1 --to nld1917 --to hboWLC
python3 scripts/unified_search.py --database /path/to/bible-research-unified.sqlite3 compare --from ugnt --book Johannes --chapter 1 --verse 1 --to russyn --to kjv --to nld1917 --tokens
```

Any edition can be the source or target, subject to book coverage. Comparisons traverse source → KJV → destination while retaining each link's status, evidence, and part labels. Links are candidates, not verified word alignments or guarantees of semantic identity. Parts, superscriptions, textual variants, unverified equal-reference rules, and transitive mappings may change scope. Two source verses sharing a KJV verse need not mean the same thing. The checked disjoint 3 John KJV verse parts are filtered; otherwise ambiguous parts must be assessed manually. An absent target is reported rather than guessed.

## Three-language search

```sh
python3 scripts/unified_search.py --database /path/to/bible-research-unified.sqlite3 search --translation nld1917 'liefde'
python3 scripts/unified_search.py --database /path/to/bible-research-unified.sqlite3 topic --ru-term любов --en-term love --nl-term liefde --limit 50
```

The application or assistant supplies synonyms and, for a multilingual question, translations of the search concepts. The script does not translate requests: literal text search and passage prefix search are lexical, not a semantic vector model, and cannot guarantee all relevant passages. Evaluate returned candidates and context. Hebrew/Greek literal search ignores diacritics. `--tokens` exposes source morphology and word attributes without implying alignment.

Set `UNIFIED_TEST_DB` to a built file and run `python3 -m unittest discover -s tests -p 'test_unified_bible.py' -v` for integration tests.
